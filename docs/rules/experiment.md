# 実験ルール（ディレクトリ構成・成果物管理）

## 1実験 = 1ディレクトリ

- 実験は `exp/expNNN/`（連番）に置く。**1つのディレクトリで複数の実験を行わない**（再現性の確認を容易にするため）。
- 新しい構造・新しい狙いの実験は必ず新しい expNNN を切る。既存ディレクトリの流用は
  「同一レシピの単一ノブ違い」（例: ハイパーパラメータを1つだけ変えた再測定）に限る。
- 実験ごとに **GitHub Issue を1件立てる**（進行管理・結果閲覧用。`docs/rules/issues.md`）。
  仮説・事前登録ゲートは Issue body、中間結果・図は Issue コメント、最終記録は docs/ に整理する。
- 各実験ディレクトリの `NOTES.md` は**仕様・パラメータ所在・再現手順（uv run コマンド列）のみ**の最小記録とする
  （仮説・ゲート・進行・結果は Issue と docs/experiments/ 側）。
- 開始手順（採番・Issue 作成・NOTES.md 雛形・事前登録ゲート）は `/new-exp`（`.claude/skills/new-exp/SKILL.md`）に従う。

## 事前登録ゲート

- GO/NO-GO の数値基準は**モデル・エージェント実装前に** Issue body に固定する
  （例: 固定 seed/固定 fold で CV スコア ≥ X、LB との乖離が Y 未満、エラー・タイムアウト 0）。
- 判定は再現可能な評価スクリプト（固定 seed・固定分割）で行う。事後の基準変更は禁止
  （変更せざるを得ない場合は body を黙って書き換えず、コメントで理由を明記する。
  小標本の好結果は母集団で霧散する前例が多い — 検証か探索かを事前に明示する）。

## 成果物の管理

- 保存するのは**最終成果物のみ**（提出物・評価サマリ）。中間チェックポイントは残さない
  （大容量モデルの学習ログ等、必要なものは `data/` や外部ストレージに置き git には入れない）。
- **大物（モデル重み・リプレイ・特徴量キャッシュ等）は git にコミットしない**（`.gitignore` で除外）。
  一度 100MB 超をコミットすると push 時に履歴除去が必要になる。
- 収集データ（LB 履歴・特徴量・nvidia-kaggle プラグインの DB 等）の正本は `data/`（ローカル、git 外）。
  消えても `tools/` で再取得可能な設計を保つ。
